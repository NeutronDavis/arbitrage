1. OVERVIEW & OBJECTIVES
--------------------------------------------------------------------------------
Phase 2g implemented quieter logging, heartbeat telemetry, persistent stats
snapshotting, and updated summarizer reporting for the Arbitrum arbitrage bot.
The scanner evaluates cross-venue opportunities between Uniswap V3 and
PancakeSwap V3, but instead of logging thousands of un-actionable negative rows
to disk every minute, it logs only opportunities meeting a spread threshold
while preserving full distribution metrics and per-market block telemetry.

Key requirements & constraints strictly maintained:
- Read-only execution: no wallet, no transactions, no PRIVATE_KEY.
- Security constraints: no .env files created, edited, read, or deleted; no secrets
  or RPC URLs printed.
- Token immutability: tokens.toml and reviewed flags left completely untouched.
- Test hygiene: test runs bounded by timeout, logging only to temporary files
  (data/test_phase2g.jsonl), leaving data/opportunities.jsonl pristine.
- Phase boundary: Phase 3 (execution / transactions) not started.

2. COMPONENT CHANGES & ARCHITECTURE
--------------------------------------------------------------------------------

2.1 Threshold Logging (LOG_MIN_SPREAD_BPS)
- Config parameter: `log_min_spread_bps` in `arb/bot/src/config.rs` (default: -2.0).
- Startup warning: If `log_min_spread_bps > -1.0`, a warning is logged to stderr
  because the persistence analysis view requires data at or below -1.0 bps.
- Filtering logic (`filter_records_by_threshold` in `arb/bot/src/strategy.rs`):
  Full opportunity rows are written to `OUTPUT_FILE` only when:
    gross_spread_bps >= log_min_spread_bps  OR  gross_spread_bps > 0.0
  Positive spreads (> 0.0 bps) are ALWAYS written regardless of the threshold.

2.2 Heartbeat Telemetry (*.heartbeat.jsonl)
- Config parameter: `heartbeat_file` (default: `<OUTPUT_FILE>.heartbeat.jsonl`).
- Records one line per market per processed block containing:
    - timestamp (u64 unix seconds)
    - block_number (u64)
    - pair (String, e.g. "WETH/USDC")
    - best_spread_bps (f64)
    - best_venue_a (String)
    - best_venue_b (String)
    - best_direction (String)
    - best_size_weth (f64)
- Written and flushed (`flush()`) on every processed block.

2.3 Stats Snapshot (*.stats.json)
- Config parameter: `stats_file` (default: `<OUTPUT_FILE>.stats.json`).
- Tracks per group (`pair`, `venue_a`, `venue_b`, `direction`, `size_weth`):
    - sample_count (u64)
    - max_spread_bps (f64)
    - min_spread_bps (f64)
    - sum_spread_bps (f64)
    - 0.5 bps bucket histogram from -100.0 to +10.0 bps (220 buckets),
      plus underflow (< -100.0 bps) and overflow (> +10.0 bps) buckets.
- Persistence across restarts: On startup, the bot loads the existing stats file
  if present and continues accumulating sample counts and histogram frequencies.
- Atomic writes: Snapshots are written to a temporary file (`*.tmp`) and renamed
  atomically (`fs::rename`) to prevent corrupt or partial reads by external processes.
- Snapshot schedule: Written on the first processed block, every 10 minutes
  thereafter, and on clean shutdown (SIGINT / Ctrl+C handler).

2.4 Summarizer Updates (`arb/bot/src/bin/summarize.rs` & `arb/bot/src/summary.rs`)
- Reads:
    1. Opportunity rows file (`OUTPUT_FILE`)
    2. Companion heartbeat file (`<OUTPUT_FILE>.heartbeat.jsonl` if present)
    3. Companion stats snapshot file (`<OUTPUT_FILE>.stats.json` if present)
- Group metrics:
    - Blocks seen, rows logged, max spread, rows > 0, USD >= min.
    - Approximate median and P95 calculated from the 0.5 bps histogram,
      explicitly documented with a disclaimer:
      "* Note: Median and P95 values are APPROXIMATE, calculated from the 0.5 bps bucket histogram."
    - Persistence runs: Tracks consecutive sampled blocks with spread > -1 bps and > 0 bps,
      treating unlogged blocks as below the threshold.
- Per-market summary table:
    - Generated from heartbeat records: min, median, max best spread,
      and percentage of blocks > -2 bps, > -1 bps, and > 0 bps.
- Backwards compatibility: Summarizer seamlessly processes legacy files that do
  not have heartbeat or stats snapshot files.

7. ANSWERS TO SPECIFIC QUESTIONS
--------------------------------------------------------------------------------

Q1: Does dotenv override environment variables set in the shell / PowerShell?
Answer:
No. In Rust, `dotenvy::dotenv()` only injects variables into the environment if
they are not already set. It will NEVER overwrite an existing environment variable.
Therefore, any variable set in the shell (e.g. `$env:OUTPUT_FILE = "..."`) takes
absolute precedence over values in `.env`.

Q2: What wrote 192 rows in block 512201215?
Answer:
In `data/markets.json`, the scanner evaluates all directed combinations between
every pair of venues for each configured size tier:
  Evaluated combinations per market = Venues * (Venues - 1) * Number of sizes
In block 512201215, the reviewed markets evaluated were:
  - WETH/USDC (6 venues, 3 sizes): 6 * 5 * 3 = 90 rows
  - WETH/WBTC (3 venues, 3 sizes): 3 * 2 * 3 = 18 rows
  - WETH/USDT (4 venues, 3 sizes): 4 * 3 * 3 = 36 rows
  - WETH/ARB  (3 venues, 3 sizes): 3 * 2 * 3 = 18 rows
  - WETH/USDC.e, LINK, GMX, AAVE, PENDLE (2 venues, 3 sizes each): 5 * (2 * 1 * 3) = 30 rows
  Total: 90 + 18 + 36 + 18 + 30 = 192 evaluated rows.
Before Phase 2g, the scanner logged every evaluated combination to disk, regardless
of spread, generating exactly 192 rows for that block.

Q3: What does `run_logger.ps1` do and which file does it write to?
Answer:
`run_logger.ps1` (located in `arb/bot/`):
1. Archives existing `data/opportunities.jsonl` by moving it to `data/old-<timestamp>.jsonl`.
2. Compiles the binary using `cargo build --release`.
3. Enters an infinite restart loop: runs `target/release/arb-bot.exe` and redirects
   console stdout and stderr to `data/bot.log`. If the bot process exits, it sleeps
   5 seconds and restarts it.
Files it writes to:
- Console log: `data/bot.log`.
- Opportunity rows: Because `run_logger.ps1` does NOT define `OUTPUT_FILE`, `arb-bot`
  uses its default setting (`data/opportunities.jsonl`). Under Phase 2g, it also
  writes `data/opportunities.jsonl.heartbeat.jsonl` and `data/opportunities.jsonl.stats.json`.

8. RUN COMMANDS
--------------------------------------------------------------------------------

A. Run Pool Discovery:
   cargo run --release -j 1 -- --discover

B. Run Scanner with Custom Shell OUTPUT_FILE + Restart Loop:
   # PowerShell (run from arb/bot)
   $env:OUTPUT_FILE = "data/scanner_run_$(Get-Date -Format 'yyyyMMdd_HHmmss').jsonl"
   $env:LOG_MIN_SPREAD_BPS = "-2.0"

   while ($true) {
       Write-Host "[$(Get-Date -Format 'yyyy-MM-dd HH:mm:ss')] Starting arb-bot with output: $env:OUTPUT_FILE"
       & .\target\x86_64-pc-windows-gnu\release\arb-bot.exe
       Write-Host "[$(Get-Date -Format 'yyyy-MM-dd HH:mm:ss')] Bot exited ($LASTEXITCODE). Restarting in 5s..."
       Start-Sleep -Seconds 5
   }

C. Run Summarizer on an Output File:
   # PowerShell (run from arb/bot)
   .\target\x86_64-pc-windows-gnu\release\summarize.exe data/scanner_run_20261010_160000.jsonl --top 20
