2. PART 1: SUMMARIZER FIXES & RECONCILIATION
--------------------------------------------------------------------------------

2.1 Reconciling Max Spread Inconsistency
- Problem: In bounded tests, the heartbeat table showed WETH/USDC best spread
  max at -1.31 bps, while the top group ranking table showed max spread at
  -2.72 bps.
- Root Cause:
  1. The group ranking table relied on `se.max_spread_bps` from the stats
     snapshot or approximate histogram if unlogged, or failed to combine
     the max of logged opportunity rows with the stats snapshot max.
  2. If an opportunity had a spread between -2.0 bps (the log filter threshold)
     and -1.31 bps, it was logged to rows, but if the group stats snapshot was
     stale or not reconciled against the logged rows, the group table retained
     the lower max.
- Resolution (`arb/bot/src/summary.rs`):
  1. The true maximum spread for any group is computed as:
       `true_max = stats_entry.max_spread_bps.max(logged_rows_max)`
  2. If logged rows contain higher observed spreads than the stats file, the
     exact observed row max takes precedence.
  3. Added unit test `test_reconciliation_exact_max_overrides_stale_stats`
     in `src/summary.rs` to guarantee regression prevention.

2.2 Header & Footer "Total Blocks Seen" Count
- Problem: The summarizer header printed `Total blocks seen: 186` after a run of
  only 14 sampled blocks, because it summed the `sample_count` across all 186
  groups rather than counting unique blocks.
- Resolution (`arb/bot/src/summary.rs`):
  1. The unique block numbers are tracked across all heartbeat records and all
     logged opportunity rows in a `HashSet<u64>`.
  2. `total_blocks_seen` is computed as:
       `unique_blocks.len().max(max_single_group_sample_count)`
  3. In bounded tests with 14 sampled blocks, the header and footer now
     consistently print:
       `Total blocks seen: 14`

2.3 PENDLE Heartbeat Telemetry Investigation
- Problem: In Phase 2g bounded tests, PENDLE logged 0 heartbeat records despite
  being in `tokens.toml`.
- Root Cause Analysis:
  1. Arbitrage requires at least 2 distinct venues for a market to evaluate
     cross-venue spreads.
  2. In `data/markets.json`, PENDLE was configured with two Uniswap V3 pools:
     - UniV3-3000 (`0x58A3660...`): Depth ~16.5 WETH (passed >= 10 WETH filter).
     - UniV3-500  (`0xB08a82e...`): Depth ~8.16 WETH (failed >= 10 WETH filter).
  3. At runtime, the depth filter dropped the 500-fee pool, leaving only 1 pool.
     With only 1 active venue, no cross-venue spread could be computed, so
     PENDLE was skipped during evaluation.
- Resolution:
  1. Camelot V3 has a dedicated WETH/PENDLE Algebra pool (`0xE461f52968B25...`)
     with 12.43 WETH reserve (exceeding the 10 WETH threshold).
  2. With Camelot V3 integrated, PENDLE now has 2 viable venues (UniV3-3000 and
     Camelot-dyn) and logs 100% of heartbeat lines across all sampled blocks.

3.2 Algebra Quoter & Factory ABI Mechanics
- Quoter Interface (`IAlgebraQuoter`):
    `function quoteExactInputSingle(address tokenIn, address tokenOut, uint256 amountIn, uint160 limitSqrtPrice) external returns (uint256 amountOut, uint16 fee)`
    - Selector: `0xa9235e16`
    - Dynamic Fee: Returned as `uint16 fee` representing hundredths of a pip
      ($100 = 1\text{ pip} = 1.00\text{ bps}$).
    - Unlike Uniswap V3, there is NO static `fee` argument passed in the call.
- Factory Interface (`IAlgebraFactory`):
    `function poolByPair(address tokenA, address tokenB) external view returns (address pool)`
    - Returns `0x0` if no pool exists.
- Pool Interface (`IAlgebraPool`):
    `function fee() external view returns (uint16)`
    `function dataStorageOperator() external view returns (address)`
    `function globalState() external view returns (uint160,int24,uint16,uint16,uint8,uint8,bool)`

3.3 Core Code Implementation (`arb/bot/src/pricing/camelot_v3.rs`)
- Alloy Sol Interface Definitions:
    - Generated `IAlgebraQuoter`, `IAlgebraFactory`, and `IAlgebraPool` interfaces.
- Calldata Building:
    - `build_camelot_v3_quote_call(token_in, token_out, amount_in)` crafts
      the exact 132-byte payload targeting the Quoter with `limitSqrtPrice = 0`.
- Quote Decoding:
    - `decode_camelot_v3_quote(data)` extracts `(U256 amount_out, u16 fee)`.
    - Converts `fee` to basis points: `fee_bps = (fee as f64) / 100.0`.
- Pool Discovery:
    - `discover_camelot_v3_pool(provider, factory, token_a, token_b)`
      queries `poolByPair` on-chain.
    - Evaluates WETH depth and computes impact ladder across [0.01, 0.05, 0.10, 0.50, 1.00] WETH.
